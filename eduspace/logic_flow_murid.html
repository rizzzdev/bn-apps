Siswa memilih mata pelajaran, lalu sistem memeriksa status setiap modul. Modul dikunci jika prasyarat belum selesai. Saat modul selesai, XP otomatis dicatat via trigger database.

Siswa memfilter dan mencari materi. Sistem menyajikan konten sesuai tipe — video dengan tracking durasi, PDF dengan tracking scroll. XP hanya diberikan satu kali per modul, kunjungan ulang masuk mode review.

Tugas reguler melewati jalur submit → tunggu penilaian guru. Kuis melewati jalur prasyarat → timer → nilai otomatis. Keduanya memberikan XP, dengan bonus jika tepat waktu atau nilai tinggi. Ada proteksi deadline dan cek prasyarat.

Halaman nilai sepenuhnya read-only untuk siswa. Semua data diambil dari pengumpulan_tugas yang sudah dinilai. Peringkat dihitung secara real-time dengan membandingkan rata-rata semua siswa satu kelas. Unduh rapor sementara digenerate di server.

Forum memiliki dua jalur utama: membuat thread baru dan membalas thread. Sistem memproteksi dengan rate limit harian dan validasi panjang konten untuk mencegah farming XP. Guru bisa menandai jawaban terbaik untuk XP bonus.
flowchart TD A([Buka Forum Diskusi]) --> B[Fetch forum_diskusi\nWHERE mapel_id IN mapel kelas siswa\nORDER BY dikirim_pada DESC] B --> C[Render daftar thread\ndengan badge status:\nMenunggu / Terjawab] C --> D{Aksi siswa} D -->|Filter mapel| E[Re-fetch WHERE mapel_id\nUPDATE tampilan] D -->|Buat pertanyaan| F[Tampilkan form:\nJudul dan isi pertanyaan] D -->|Klik thread| G[Fetch semua reply\nWHERE parent_id = thread.id\nORDER BY dikirim_pada ASC] E --> C F --> H{Validasi panjang:\nisi ≥ 20 karakter?} H -->|Terlalu pendek| I[Error: Pertanyaan\nterlalu singkat] H -->|OK| J{Rate limit:\nPostingan hari ini\nuntuk mapel ini < 3?} J -->|Limit tercapai| K[Error: Batas posting\nharian tercapai] J -->|OK| L[INSERT forum_diskusi\npengirim_siswa_id, mapel_id,\nisi, dikirim_pada = NOW] L --> M[INSERT xp_log\n+8 XP untuk posting pertanyaan] M --> N[INSERT notifikasi\nuntuk guru mapel terkait] N --> O[Tampilkan thread baru\ndengan badge Menunggu] G --> P{Guru sudah membalas?} P -->|Ya| Q[Tampilkan balasan guru\ndengan border teal + label Guru] P -->|Belum| R[Tampilkan badge Menunggu\ndi header thread] Q --> S{Guru tandai\njawaban terbaik siswa?} S -->|Ya| T[INSERT xp_log\n+20 XP untuk siswa terpilih\nINSERT notifikasi ke siswa] G --> U{Siswa ikut membalas?} U -->|Ya| V{Validasi:\nisi balasan ≥ 10 karakter?} V -->|Tidak| W[Error: Balasan terlalu singkat] V -->|Ya| X[INSERT forum_diskusi\nparent_id = thread.id] X --> Y[INSERT xp_log\n+5 XP untuk membalas] D -->|Like post| Z{Sudah like\npost ini sebelumnya?} Z -->|Belum| AA[INSERT forum_like\nnaikan like_count] Z -->|Sudah| AB[DELETE forum_like\nToggle unlike] style A fill:#EEEDFE,stroke:#534AB7,color:#26215C style I fill:#FCEBEB,stroke:#E24B4A,color:#791F1F style K fill:#FCEBEB,stroke:#E24B4A,color:#791F1F style W fill:#FCEBEB,stroke:#E24B4A,color:#791F1F style L fill:#E1F5EE,stroke:#1D9E75,color:#085041 style M fill:#FAEEDA,stroke:#BA7517,color:#633806 style T fill:#FAEEDA,stroke:#BA7517,color:#633806
Halaman sosial yang menampilkan sesama siswa dalam satu kelas. Data yang tampil dibatasi untuk privasi — nilai detail dan tugas tidak bisa dilihat oleh teman. Fitur pencarian dan sorting diproses di sisi klien tanpa request baru ke server.

Profil memiliki dua mode: view dan edit. Perubahan divalidasi dua lapis (frontend + backend). Ubah kata sandi menggunakan bcrypt dan mengirim email konfirmasi. Semua riwayat XP diambil dari tabel xp_log dengan paginasi.
