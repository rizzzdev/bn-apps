# Exam Backend API

REST API untuk sistem manajemen ujian online berbasis Express.js 5 + TypeScript + Prisma 7 + PostgreSQL.

## Tech Stack

| Layer | Library |
|---|---|
| Runtime | Node.js 20+ |
| Framework | Express.js 5 |
| Language | TypeScript 6 (strict, ESM) |
| ORM | Prisma 7 + `@prisma/adapter-pg` |
| Database | PostgreSQL 16 |
| Validation | Zod v4 |
| Logging | Pino + pino-http |
| Security | Helmet, CORS, express-rate-limit |
| Auth | JSON Web Token + bcrypt |

src/

## Getting Started

### Prerequisites

- Docker & Docker Compose (untuk menjalankan full stack)
- Node.js 20+ (hanya untuk development lokal)

---

### Opsi A — Full Stack dengan Docker Compose (Recommended)

Jalankan database **dan** backend sekaligus dalam satu perintah:

```bash
docker compose up -d --build
```

Layanan yang berjalan:

| Service | Container | Port |
|---|---|---|
| PostgreSQL 16 | `exam_bn_postgres` | `5432` |
| Express Backend | `exam_bn_backend` | `3000` |

Migrasi database dijalankan otomatis saat container backend start.

API tersedia di `http://localhost:3000`.

**Token secret** dapat di-override lewat file `.env` di direktori yang sama:

```env
ACCESS_TOKEN_SECRET_KEY=your_secret_here
REFRESH_TOKEN_SECRET_KEY=your_secret_here
```

Docker Compose akan membaca kedua variabel ini dari `.env` jika tersedia.

---

### Opsi B — Development Lokal (Node.js)

#### 1. Install dependencies

```bash
npm install
```

#### 2. Jalankan hanya database

```bash
docker compose up -d postgres
```

PostgreSQL berjalan di `localhost:5432` dengan:

| Config | Value |
|---|---|
| Database | `exam_db` |
| User | `exam_user` |
| Password | `exam_password` |

#### 3. Konfigurasi environment variables

```bash
cp .env.example .env
```

`.env` sudah dikonfigurasi untuk terhubung ke container Docker di atas (`DEV_DB_URL` sudah diisi).

#### 4. Jalankan migrasi database

```bash
npm run db:migrate
```

#### 5. Start development server

```bash
npm run dev
```

API tersedia di `http://localhost:3000`.

## Standard Response Format

All endpoints return a consistent JSON envelope:

```json
{
  "error": false,
  "statusCode": 200,
  "message": "Success",
  "data": { }
}
```

**Error response:**

```json
{
  "error": true,
  "statusCode": 404,
  "message": "Resource not found",
  "data": null
}
```

**HTTP status codes used:**

| Code | Meaning |
|---|---|
| `200` | OK |
| `201` | Created |
| `400` | Bad Request / Validation Error |
| `401` | Unauthorized |
| `403` | Forbidden |
| `404` | Not Found |
| `429` | Too Many Requests |
| `500` | Internal Server Error |

### Users

Base path: `/api/v1/users`

#### GET /api/v1/users

**Query Parameters:**

| Parameter | Type | Description |
|---|---|---|
| `page` | `number` | Page number (default: 1) |
| `limit` | `number` | Items per page (default: 10) |
| `username` | `string` | Filter by username (partial match) |
| `role` | `string` | Filter by role: `ADMIN`, `SUPERVISOR`, `PARTICIPANT` |
| `loginAudits` | `boolean` | Include related login audits (`true`) |
| `examParticipants` | `boolean` | Include related exam participants (`true`) |
| `examSupervisors` | `boolean` | Include related exam supervisors (`true`) |

**Response `200`:**
```json
{
  "error": false,
  "statusCode": 200,
  "message": "Get users data successfully.",
  "data": [
    {
      "id": "cuid25chars",
      "fullname": "John Doe",
      "username": "johndoe",
      "passwordHash": "$2b$...",
      "role": "PARTICIPANT",
      "createdAt": "2024-01-01T00:00:00.000Z",
      "updatedAt": "2024-01-01T00:00:00.000Z",
      "deletedAt": null
    }
  ]
}
```

#### GET /api/v1/users/:id

**Query Parameters:**

| Parameter | Type | Description |
|---|---|---|
| `loginAudits` | `boolean` | Include related login audits |
| `examParticipants` | `boolean` | Include related exam participants |
| `examSupervisors` | `boolean` | Include related exam supervisors |

**Response `200`:** Single user object.
**Response `404`:** User not found.

#### POST /api/v1/users

**Request Body:**

| Field | Type | Required | Description |
|---|---|---|---|
| `fullname` | `string` | Yes | Max 255 chars |
| `username` | `string` | Yes | Unique, max 100 chars |
| `passwordHash` | `string` | Yes | Plain password (min 6 chars) — hashed in service layer |
| `role` | `string` | Yes | `ADMIN` \| `SUPERVISOR` \| `PARTICIPANT` |

**Response `201`:** Created user object.
**Response `400`:** Validation error or username already taken.

#### PATCH /api/v1/users/:id

All fields from POST body are optional.

**Response `200`:** Updated user object.
**Response `404`:** User not found.

#### DELETE /api/v1/users/:id

Soft delete — sets `deletedAt` timestamp.

**Response `200`:** Deleted user object.
**Response `404`:** User not found.

## Data Model Overview

```
Room (1) ─────────────────────── (n) ExamRoom (n) ──── (1) Exam
                                        │
                    ┌───────────────────┼─────────────────────┐
                    │                   │                      │
           ExamParticipant[]    ExamSupervisor[]        ExamQuestion[]
              (User →)              (User →)             (Question →)
                    │
           ExamAnswer[]     ExamScore[]
        (User →, Question →, Option →)  (User →)

Question
 ├── Option[]
 ├── QuestionCorrectAnswer  (→ Option)
 └── ExamQuestion[]

User
 ├── LoginAudit[]
 ├── ExamParticipant[]
 ├── ExamSupervisor[]
 ├── ExamAnswer[]
 └── ExamScore[]
```

### Enums

| Enum | Values |
|---|---|
| `UserRole` | `ADMIN`, `SUPERVISOR`, `PARTICIPANT` |
| `QuestionType` | `MULTIPLE_CHOICE`, `ESSAY` |

### Soft Delete

Models dengan `deletedAt DateTime?` (soft delete):
`User`, `Room`, `Exam`, `ExamRoom`, `Question`, `Option`, `ExamQuestion`

Models tanpa `deletedAt` (hard delete):
`LoginAudit`, `ExamParticipant`, `ExamSupervisor`, `QuestionCorrectAnswer`, `ExamAnswer`, `ExamScore`

## Docker Compose

```bash
# Build dan start semua layanan (pertama kali atau setelah ada perubahan kode)
docker compose up -d --build

# Start tanpa rebuild
docker compose up -d

# Lihat log backend
docker compose logs -f backend

# Lihat log database
docker compose logs -f postgres

# Stop semua layanan
docker compose down

# Stop dan hapus volume data (reset database)
docker compose down -v

# Rebuild hanya backend
docker compose build backend
docker compose up -d backend
```
